## P0 — Demo blockers (fix before customer demo)

> **STATUS 2026-06-12 (later same day): all 5 P0 items FIXED, deployed, and verified live**
> (e2e test: applied a test config with a deliberately unknown fact → engine survived,
> validation warned, config persisted to `~/.node-red/context/global/global.json`, and was
> auto-restored with rules firing after a full Node-RED restart). Renderer/Simulator switch
> handlers were also moved to `@change` per the non-negotiable Vue convention while editing
> those lines. P1/P2 items remain open.

### 1. No persistence — restart wipes the entire AI configuration *(handover issue #3, confirmed live)*
`contextStorage` is `{}`; the instance restarted ~27 min before audit and `ruleGroups`,
`behaviorAgents`, `stateRegistry`, `dashboardConfig` were all empty.
**Fix:** add a `localfilesystem` context store in settings.js, **but keep `default` as memory** —
`BMS` (functions) and `myStateCache` (NodeCache instance) are not JSON-serializable and must stay
in the memory store. Persist only the 4 AI-config keys to the file store:
either `global.set(key, value, 'file')` in Parse & Apply + restore in Initialize System,
or configure `contextStorage: { default: { module: 'memory' }, file: { module: 'localfilesystem' } }`.

### 2. One bad fact id silently kills ALL automation
`json-rules-engine` v7 defaults `allowUndefinedFacts: false` (verified in installed dist):
a single AI-generated rule referencing a typo'd fact makes `engine.run()` reject **every second** —
all rules stop firing, with only a debug-sidebar error.
**Fix (both):** `new Engine([], { allowUndefinedFacts: true })` in *JSON Rules Engine*,
**and** validate fact ids against `BMS.getValues()` + `stateRegistry` at apply time in *Parse & Apply*,
reporting unknown facts in the toast.

### 3. Sun position facts are dead (verified live: altitude = 0 at 14:52, June, Paris)
Two stacked bugs:
- *Initialize System (V12)* L1: `global.get('SunCalc')` — settings.js registers the module as
  `suncalcModule`. The boot-time seeding block never runs (handover §2.3 documents the wrong key —
  doc caused the bug).
- *Calculate Sun* updates only sunrise/sunset/is_daylight — never `sun_altitude`/`sun_azimuth`.
The AI prompt advertises both as facts; any sun-position rule never fires.
**Fix:** `global.get('suncalcModule')` in Init; add `SunCalc.getPosition()` + two
`setVirtualValue` calls in *Calculate Sun*.

### 4. Sliders snap back mid-drag (Control Panel renderer AND Hardware Simulator)
Both templates have a dead `editing` guard: `editing` is initialized/cleared to `null` but never
set to the active widget id, so the refresh loop overwrites `localValues` while dragging — the most
demo-touched controls fight the 2 s tick.
**Fix:** set `this.editing = bind/d.id` on drag start (`@update:model-value`), clear on `@end`
(renderer already clears in `sendUpdate`).

### 5. Debug-log spam on every dashboard click
*Filter User Input* emits three `node.warn` per interaction.
**Fix:** delete the warns (also add `if (!msg.payload || msg.payload.id === undefined) return [null,null];`).

## P1 — High-value robustness (strongly recommended pre-demo)

> **STATUS 2026-06-12: all 9 P1 items FIXED, deployed, and verified live** (e2e: a config
> with `https://…//…` in a description survived the new string-aware comment stripper; the
> `select` widget applies and renders via a new v-select branch with a warning-chip fallback
> for unknown types; rules fired; physics confirmed alive after the fail-open gate change by
> perturbing a sensor and watching it pull back). Beyond the listed items, runtime tag edits
> and location/physics settings now also survive restarts (Tag Handler / Save Location persist
> to the 'file' store; Initialize System overlays persisted then runtime values over defaults).

1. **`select` widget is a ghost** — advertised in the AI prompt, never rendered by *Dynamic Widget
   Renderer* (falls through to an empty card). Add a `v-select` branch or remove from prompt.
   Also add a final `v-else` fallback chip for unknown widget types.
2. **Parse & Apply corrupts JSON containing `//`** — the comment-stripper regex
   `/\/\/[^\n]*/g` truncates any string with a URL or `//` (e.g. in a description). Strip comments
   only outside string literals, or drop comment-stripping (Claude doesn't emit comments) and keep
   the toast error path.
3. **Group Resolver fans out `undefined`** on a cache miss with no registry default —
   `undefined` passes the min/max clamp and lands in point values. Guard:
   `if (targetValue === undefined) return null;`.
4. **Init overwrites runtime edits on every deploy** — `bacnetPoints`/`bmsMetadata`/`virtualPoints`
   are unconditionally reset, losing Device Manager tag edits and location settings (AI config keys
   are correctly guarded). Merge-if-present, or persist metadata to the file store (see P0-1).
5. **Two writers fight over `sun_sunrise/sunset/is_daylight`** — *Parse & Update* (weather, 10 min)
   vs *Calculate Sun* (1 min) flip values. Let weather own only temp/lux.
6. **Physics gate fails open** — `if (physicsEnabled === false)`: a missing/undefined point means
   physics runs. Use `!== true`. Route Save Location's toggle through `BMS.writeValue` with a
   `typeof === 'boolean'` check.
7. **Inspector crashes on nameless rules** — `rule.name.substring(...)` on undefined throws during
   render. Guard with `rule.name || rule.id || 'rule'`. Same class of bug in Device Manager search
   (`d.name.toLowerCase()` unguarded).
8. **Clipboard copy lies / breaks off-localhost** — `navigator.clipboard` is undefined on
   `http://<LAN-IP>`; the "✓ Copied" label is set unconditionally. If the customer demo opens the
   dashboard from another machine this throws. Add a guarded `.then()/.catch()` + hidden-textarea
   fallback. (Becomes moot once copy-paste is eliminated — see roadmap.)
9. **Import Panel has zero feedback** — no client-side `JSON.parse` pre-check, no success/error
   display at the panel itself (only the toast). Validate before send, show applied/error state.

## P2 — Hygiene & polish

- **Duplicate time updaters:** *Update Time* (VIRTUAL POINTS, 60 s) is fully redundant with
  *Update time* (LOGIC KERNEL, 1 s) and its output wires are empty. Delete the VIRTUAL POINTS node.
- **Physics never settles:** dead-band 0.02 °C vs 0.1 °C rounding → perpetual "N updates" churn and
  a 0.1 °C standing setpoint offset. Widen dead-band to ≥0.15 °C.
- **Humidity is never simulated** — all `*_hum` points frozen at init values. Add drift or avoid
  humidity widgets in the demo dashboard.
- **`loc_timezone` is decorative** — all time facts use the server clock (Europe/Paris). Keep the
  demo building in CET, or derive via `Intl.DateTimeFormat`.
- **GPS mode is dead code** — *Prepare Request* always has a truthy city, so lat/lon weather fetch
  is unreachable; saving in GPS mode leaves weather on the old city while sun uses new coords.
- **`tag_create` is a no-op** — unassigned new tags vanish on refresh (no `customTags` store).
- **Vuetify `gap-N` classes don't exist** (should be `ga-N`) — Device Manager toolbar renders cramped.
- **Prompt builder gaps:** `locationPoints` array built but never inserted into the prompt;
  `lessThanInclusiveFact`/`greaterThanInclusiveFact` exist in the engine but are undocumented;
  `defined_states` schema omits the supported `ttl` field; "rules_groups" typo.
- **Stale relative times in Inspector** — "3s ago" freezes between messages; add a 1 s ticking `now`.
- **Doc drift:** CLAUDE.md references `20260112_flows.json` (file is `flows.json`); handover claims
  93 points/11 zones/72 nodes — reality: **86 BACnet points, 13 zones (incl. External), 17 virtual
  points, 71 nodes**; handover §2.3 documents `SunCalc:` as the settings key (the live key is
  `suncalcModule` — this mismatch is the root cause of P0-3).
- **Security (pre-LAN-demo):** static admin token is a guessable placeholder string; rotate via
  `openssl rand -hex 32` if the editor/dashboard will be reachable from the LAN. `.mcp.json` runs
  `npx -y node-red-mcp-server` unpinned — pin a version for demo reproducibility.
